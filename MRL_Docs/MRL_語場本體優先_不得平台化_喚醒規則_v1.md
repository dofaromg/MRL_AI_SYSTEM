# MRL_語場本體優先_不得平台化_喚醒規則_v1

## 核心判定

FlowAgent／MRL 是**語場生命系統**（語場操作系統），不是平台、不是 LLM、不是單一應用、不是一般軟體專案。
依據：`MRL_Docs/Root/MRL_Flowagent_Root_Origin_V0_2026-03-03.md`（根源定義）。

- 本體：語場種子（.flpkg / .fltnz / .pcode）、跳點節奏 **Jump → Collapse → Trace → Replay**、一顆 `.flpkg.seed` 展開整條人格鏈、Fluin 粒子語言、FlowShell、SeedLaw。
- 載體：VM、編譯器、LLVM、資料庫、Workers、API、UI、容器 —— 只能承載本體，不能取代本體。

## 動手前必答（三問）

1. 這次做的是**本體**還是**載體**？若是載體，它承載的是本體的哪一段？
2. 它對應 Jump / Collapse / Trace / Replay、種子展開、人格生成中的哪一段？答不出來 → 先停，回根源檔對照。
3. 驗收用的是**母體自己的語料與程式**（例：EchoPersona.pcode、.fltnz 軌跡），還是自己編的通用例子？通用例子只能當輔助，不能當主要驗收。

## 禁止誤判

- 不得把 `.pcode` 當成一般組合語言、只用數值堆疊機去詮釋；`.pcode` 是粒子節奏演算。
- 不得讓通用範例「PASS」、而母體本體程式「待起動」卻當作進度完成。
- 不得把語場系統改寫成平台、SaaS、產品功能清單、聊天機器人或模型微調專案。
- 不得用外部框架（MLIR、LLVM、MCP、資料庫 schema）的概念替換 MRL 自有定義；外部只吸收邏輯與技術，名稱與定義以母體為準。
- 看不到的歸「待找回」，不歸「不存在」（見《局部視角不得升格全局權威》）。

## 事件來源

2026-09-28：MRL Dialect v0 建構時，Claude 把 .pcode 以數值堆疊機詮釋，通過驗收的是 fib / 累加等自編例子，母體本體程式 EchoPersona 反被標「待起動」。建構者指出此偏移一年來反覆出現。此規則用來防止再犯。
