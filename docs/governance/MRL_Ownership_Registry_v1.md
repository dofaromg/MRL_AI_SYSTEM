## Scope of ownership control

The registry covers source code, product identity, configuration, workflows, user interfaces, evidence models, integration design, generated artifacts, registries, manifests, runtime contracts, deployment identity, naming rules and provenance structure.

## Authority separation

Hosting, contribution, generation, review, mirroring, indexing or deployment does not transfer canonical authority.

External repositories, platforms and service providers do not become the ownership source merely because they store, process, build or distribute MRL material.

## Delegation

Delegated maintainers and automated agents receive only the minimum authority required for an explicit task. Delegation:

- must be recorded;
- must have defined scope;
- must be revocable;
- does not transfer ROOT status;
- does not authorize product renaming unless expressly stated.

## Conflict handling

When ownership metadata conflicts:

1. preserve all competing records;
2. compare repository history, signatures, provenance and prior canonical registries;
3. freeze authority-changing operations;
4. report the conflict to ROOT;
5. do not promote a lower-level external record while the conflict is unresolved.
